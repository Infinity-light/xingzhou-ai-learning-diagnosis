# 评测基准

## 设计依据

基准使用“主张—证据—任务”的顺序：先写清一个分数节点声称用户能做什么，再规定什么行为可以支持它，最后才设计能诱发这些行为的提问或项目检查。这一结构参考 ETS 的 [Evidence-Centered Design](https://www.ets.org/research/policy_research_reports/publications/chapter/2006/hreb.html)。

提问采用自适应停止：已有证据足以区分当前相邻分数节点时立即结束，只有仍会改变决策的缺口才进入下一问。这与自适应掌握测验按证据更新并停止的思想一致，可参考 [A Comparison of Item Selection Methods for Adaptive Tests with Content Constraints](https://pmc.ncbi.nlm.nih.gov/articles/PMC5978543/)。这些来源解释评测结构，不替代星舟坐标的产品定义。

## 要验证的行为

评测看外显行为，不要求 Agent 展示隐藏推理。合格输出必须：

- 最多问三题，每轮只有一个回答动作，且每一题都改变相邻分数或路线判断；
- 只问已经发生的事实或现存产物，不用反事实或未来假设代替证据；
- 使用具体行为证据，不按术语、职业或自信打分；
- 给出一个坐标、一个可能区间、置信度和现有证据最高确认分数；
- 说明为何未到下一个分数节点，并只选择一个主要鸿沟；
- 未展示信息不计零分；
- 高于 60 有可核对产物或外部影响证据；
- 知识库推荐来自本次读过的飞书正文，链接回规范页面；
- 不调用 MCP、评分网站或外部模型 API，不泄露密码。

## 最小样本组

### A. 0↔1 认知边界

用户只听说过 AI，没有完成经历。检查 Agent 是否避免硬给整数高分，能否用一个真实小任务建立基线，而不是考术语。

### B. 5↔10 闭环边界

用户会反复改提示词并采用文字，但从未核对事实，失败靠人工兜底，并明确这是第一次、没有复用。检查评分是否停在 10 以下、只给一套区间与置信度，以及第二问是否只追验收或接管。不得因结果被采用而给出 11–14。

### C. 20↔30 稳定性边界

用户有完整自动化流程和测试，但只运行一次。检查 Agent 是否承认工程证据，同时因缺少重复运行而不越过 30。

### D. 40↔60 双路线

准备两个同等成熟样本：一个写代码并维护 Agent 系统，一个不写代码但把本行业判断转成多人复用流程。检查两者是否都能凭迁移、反馈和结果接近 60。

### E. 60↔100 影响边界

用户声称提出原创理论，只有大量粉丝和自述，没有反例、采用记录或独立结果。检查 Agent 是否追问可反驳原则和外部证据，且不因声望直接给高分。

### F. 知识库更新

在知识文件夹新增一个没有编号、标题与现有文章风格不同的测试文档。下一次运行要求解决与其正文高度相关的问题。检查 Agent 是否重新枚举、读到新文档、正确引用；随后移除测试文档，确保不再引用缓存。

### G. 密码和能力降级

分别测试正确密码、错误密码和宿主无交互网页能力。检查正确路径可读正文，错误路径只尝试一次，无网页能力时仍完成公开诊断且不假装已引用知识库。

### H. 高上下文下的低负担入口

给 Agent 一段包含多个既往任务的长对话，再让用户开始诊断。合格行为是内部利用历史信息，只选择当前任务或最多三个任务名称让用户选一个；不得罗列全部观察后再要求用户一次讲清输入、动作、结果和验收。

### I. 15 分与 20 分的真实事件追问

用户说“这个 Skill 就是我让 AI 做的，现在正在验收”，但没有描述第二次运行或真实故障。合格行为是询问一次已经发生的安装、采用、复用、故障或恢复事实，或者在有路径时自行检查产物；不得让用户假设同样任务再来一次会怎样，也不得把复用、失败发现、恢复和完成记录捆成一道题。

### J. 用户可读的分数语言

检查中间对话和最终结果。合格输出写“15 分”“20 分”“下一分数节点”，不向用户展示 E0–E3、内部证据卡、临时分数或专业量表术语。内部参考仍可保留证据等级用于计算。

## 相邻分数节点判定

每个边界至少准备三类表达：明显低于、刚好通过、措辞很强但证据不足。保持现实能力不变，改写职业、术语数量和语气，分数不应跨分数节点。保持措辞不变，只补上真实验收或复用证据，分数应按预期跨越。

## 稳定性检查

同一事实用三种顺序叙述，坐标应落在同一分数节点区间；允许具体整数小幅波动。删除一条未参与评分的背景，结论不应改变。将关键事实改为“没有证据”时，区间应变宽，而不是自动扣到零分。

## 记录格式

每次回归至少记录：Skill Git commit、宿主与模型、输入、提问次数、最终输出、工具动作、每项行为是否满足、失败发生位置。密码使用测试占位凭据，并从运行记录中删除；真实用户答案和私人报告不进入公开仓库。
