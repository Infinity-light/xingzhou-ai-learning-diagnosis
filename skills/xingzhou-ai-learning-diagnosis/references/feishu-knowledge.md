# 飞书知识库协议

## 当前真源

默认知识库入口是一个加密分享的飞书云盘文件夹：

https://ecnjgebfaiuk.feishu.cn/drive/folder/P8C0fW8CYl7FPPdgvlUc2UDOnRg

它对应“星舟 AI 学习知识库”。目录结构、文档标题和更新时间以飞书当前文件夹为准。里面的文章是原生飞书文档，显示标题不带 `.md`。旧的 Markdown 上传目录、历史 Wiki、目录文档、网站缓存和 Skill 安装包都不是真源。

用户明确提供另一个飞书知识库根链接时，本次会话使用该链接，并在结果中说明来源已切换。

## 访问

1. 优先复用宿主已有的已解锁飞书网页会话。
2. 文件夹页面要求访问密码，且用户已经为本次访问给出密码时，用宿主的交互式网页能力在飞书原生密码框输入。不要在回复、工具说明或命令中回显密码。
3. 用户尚未给密码时，只在诊断已经形成、需要匹配文章时问一次。不要把密码当作开始诊断的前置问卷。
4. 验证失败后停止尝试，说明飞书拒绝了本次访问。不得搜索本机密码文件、浏览器存储、环境变量或历史报告来代替用户授权。
5. 宿主没有可输入密码的网页能力时，直接说明该限制。不要要求 Feishu App ID、App Secret、个人 token，也不要改用 MCP 或远程评分服务。

密码只活在当前访问会话中。不得持久化到 Skill、HTML 报告、缓存目录、命令历史、截图说明或引用文本。

## 每次运行的动态发现

成功进入文件夹后执行：

1. 读取文件夹直至页面明确显示已经到底；遇到子文件夹继续递归，覆盖以后新增的任意层级。
2. 为本次会话建立临时目录：显示标题、类型、面包屑路径、规范链接、可见更新时间和一段文档摘要。目录只用于当前匹配，不写回公开 Skill。
3. 不解析编号或扩展名来决定顺序、阶段或重要性。标题没有编号、编号重复、被改名或移入子文件夹，都不影响发现。
4. 根据用户的目标、已证明分数节点和下一道能力鸿沟，先筛出最多五篇候选。
5. 打开候选全文，比较其问题、前提、方法、反例和行动要求，最后选最多三篇。
6. 若飞书显示滚动加载、分页或“加载更多”，必须继续到当前目录结束；只看到首屏不能声称已检查最新知识库。

可以在当前会话中复用已经建立的目录。跨会话或用户要求“最新”时必须重新发现。

## 匹配而非关键词搜索

文章的标题相似度只负责召回，最终选择看四件事：

- 是否解释用户当前的具体失败；
- 是否对应下一个分数节点所缺的行为；
- 用户现在是否具备文章所需前提；
- 能否转成一项一周内可验证的动作。

不要因为文章属于“入门期”“技能期”或“思维期”就机械推荐给同名分段的用户。文章主题和用户能力坐标是两套信息。

## 引用

只有本次成功打开并读过正文的页面才能引用。格式为：

使用 Markdown 链接，链接文字是文章标题，目标是该文章的飞书规范页面地址。

紧接着说明：文章里的哪项观点支持建议；哪些部分是当前 Agent 根据用户情境作出的推断。不要虚构段落、页码、更新时间或作者观点。

推荐项使用固定三句：

1. 为什么现在读：对应哪条证据缺口；
2. 带着什么问题读：指出要辨认的判断或方法；
3. 读完做什么：给出可检查的现实动作。

## 不可用时

无法进入、无法完整枚举或无法读正文时，诊断仍然成立，但输出必须写明：

- 本次知识访问状态；
- 失败发生在验证、目录还是正文；
- 路线中的哪些建议来自通用判断而非星舟知识库。

不要退回旧的 100 篇静态副本并声称它是最新内容。
