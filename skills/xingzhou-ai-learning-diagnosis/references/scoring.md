# 0–100 非线性学习坐标

## 坐标的含义

这条坐标描述一个人把 AI 变成现实行动、可靠结果和可迁移判断的程度。相邻数字不是等量知识，60 分也不表示“掌握了 60%”。三个宽层级是：

| 区间 | 宽层级 | 核心变化 |
| --- | --- | --- |
| `[0,1)` | 认知期 | 从没有形成可用认识，到开始把真实问题交给 AI |
| `[1,10)` | 技艺期 | 从偶尔问答，到能通过上下文、迭代和检查完成一个任务 |
| `[10,100]` | 思维层 | 从个人闭环，到稳定系统、跨情境迁移、原创判断和行业贡献 |

10 以上允许两条等价路线：工程路线用系统、工具、评测和可靠性创造结果；领域路线把本行业的判断、约束和反例转化为 AI 可执行的方法。非技术专家不因不写代码而被压低分数。

## 证据等级

| 等级 | 含义 | 对评分的作用 |
| --- | --- | --- |
| E0 | 没有提到或无法判断 | 标为未知，不当作失败 |
| E1 | 只有概括性自述 | 可形成暂定区间，置信度低 |
| E2 | 有具体任务、动作、结果和判断 | 可以托住相应锚点 |
| E3 | 实际产物、日志、版本、评测、用户结果或可复核影响 | 可以收窄区间；60 以上通常需要 |

语言是否专业不改变证据等级。一个新手用朴素语言讲清完整闭环，证据可以高于只会列概念的人。

## 行为锚点

| 锚点 | 已经稳定表现出的能力 | 跨过它所需的关键证据 |
| ---: | --- | --- |
| 0 | 尚未形成可判断的 AI 使用经验 | 不把“没说”误判成“不会” |
| 1 | 能把一个真实问题交给 AI，并意识到输出需要人判断 | 至少一次具体尝试，能说清想解决什么 |
| 3 | 会补上下文、约束或示例，能针对第一版继续调整 | 一次具体的前后修改，而非只说“我会提示词” |
| 5 | 能拆开一个有限任务，比较结果并把输出用于现实工作 | 输入、迭代和采用结果三者可追溯 |
| 7 | 能发现明显错误或缺口，修正后完成一次个人闭环 | 有验收动作，能指出哪里仍由人接手 |
| 10 | 能独立把一个有边界的任务从目标推进到可接受结果 | 目标、行动、外部事实或工具、验收、停止条件形成闭环 |
| 15 | 同一类任务可以再次完成，不再依赖偶然灵感 | 至少一次复用；知道常见失败和修复办法 |
| 20 | 已把上下文、工具、检查和人工接管组织成可恢复流程 | 失败可见、状态可续、关键动作有证据 |
| 30 | 有一个被重复使用的稳定工作流或项目，并有明确成功标准 | 多次真实运行；结果可验收；责任和权限清楚 |
| 40 | 方法跨项目或跨使用者成立，开始使用回归样本和运行反馈 | 至少一次迁移证据和一次由失败引发的规则修改 |
| 50 | 能解释架构取舍，管理成本、可靠性、维护和供应商边界 | 选择有反例、有数据或事故依据，不是堆技术 |
| 60 | 形成可迁移的方法体系，能持续改变团队或领域中的实际决策 | E3 证据支持跨情境复用、长期结果和可教给他人的原则 |
| 75 | 提出可反驳的原创框架，并通过多个环境或群体修正它 | 能给出适用边界、反例和实际采用结果 |
| 90 | 方法产生持续、独立可验证的领域影响，且经受不同立场检验 | 外部长期证据，不以粉丝量或头衔替代 |
| 100 | 北极星：推进了一个领域理解和使用 AI 的方式 | 不是普通课程结业点；一次访谈不得直接授予 |

## 计算办法

1. 为用户的每条陈述建立证据卡：情境、目标、AI 行动、人的行动、结果、验收、复用、迁移、边界和证据等级。
2. 找到所有关键条件都获得 E2 支持的最高锚点 `L`。60 以上还要有 E3。职业、术语或愿望不能补齐门槛。
3. 找到下一个锚点 `U`，只检查从 `L` 到 `U` 的过渡信号。该锚点表述中的关键门槛没有出现时，不能跨越。
4. 用四档表达过渡程度：没有开始 `0`、开始出现 `0.3`、多次但不稳定 `0.6`、只缺一项关键证据 `0.9`。
5. 暂定坐标为 `L + (U-L) × 过渡程度`。1 以上四舍五入为整数，并始终低于尚未通过的 `U`；1 以下保留一位小数。

数字必须跟着文字证据。过渡档是沟通尺度，不是假装经过标准化测量。

## 不可补偿门槛

相邻锚点中的核心行为不能由其他优点抵消。先应用门槛，再计算过渡：

| 目标锚点 | 明确缺少这些证据时的上限 |
| ---: | --- |
| 10 | 只有生成、改稿或人工采用，没有目标—行动—验收—停止的完整闭环，最高 9；任务含关键对外事实却明确未核验时也最高 9 |
| 15 | 用户明确说这是第一次、从未复用，最高 10；不得用单次质量换成 11–14 |
| 30 | 流程只真实运行过一次，最高 29 |
| 40 | 没有任何跨项目、跨场景或跨使用者迁移，最高 39 |
| 60 | 没有 E3 支持的跨情境长期结果或他人采用，最高 59 |
| 75 | 没有可反驳原则、适用边界和被反例修正的记录，最高 74 |
| 90 | 没有独立、持续的外部影响证据，最高 89 |
| 100 | 一次访谈不授予，只能说明向北极星靠近的证据 |

“明确缺少”与“尚未提到”不同。前者把对应过渡记为 0；后者扩大区间或在会改变路线时追问，不能擅自当作已经具备。

10 本身不要求模板、第二次运行或跨场景复用。若判断低于 10，只能引用独立闭环、必要事实或工具、验收、失败接管或停止条件中的实际缺口；复用只能用于判断 10→15，不能倒过来压低 7→10。

同理，20 判断的是流程结构是否可恢复，不要求多次生产运行。具体证据同时覆盖工具、检查、状态、失败续接和人工接管时，可由 20 作为最高完整锚点；“只生产运行一次”只阻止它达到 30。回归样本不能冒充生产复用，但也不能抹掉已被证明的 20 分流程能力。

## 区间和置信度

- 高置信度：多个具体事件互相一致，并有 E3；区间通常不超过相邻两个过渡档。
- 中置信度：至少一个完整 E2 事件；区间可以覆盖当前锚点到下一锚点的一部分。
- 低置信度：只有 E1、自相矛盾或大量关键未知；区间可以跨一个锚点，但要说明需要什么证据才能缩小。

置信区间表达“在现有证据下可能在哪里”，展示上限表达“目前最高证明到哪里”。未知只扩大区间，不扣分；已经明确缺少的门槛会限制区间上界，区间也不能跨过去。

## 相邻锚点的解释

诊断必须用一句话说明为何没有到达下一锚点。例如：

- 7→10：做成过一次，但还没看到工具结果如何回写、失败时如何停止。
- 20→30：流程结构完整，但尚无第二次真实运行和稳定验收记录。
- 50→60：能做成熟系统取舍，但尚无跨情境迁移或他人采用的长期证据。

避免“基础不牢”“需要提升综合能力”这类无法行动的判断。
